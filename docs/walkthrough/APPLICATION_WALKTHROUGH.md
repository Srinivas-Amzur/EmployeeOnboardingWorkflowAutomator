# Application Walkthrough - Employee Onboarding Workflow Automator

## 1) Business Problem Solved
Large organizations often run onboarding through disconnected email threads, spreadsheets, and manual reminders. That creates delays in provisioning, unclear ownership, weak auditability, and poor visibility for HR and leadership.

This application centralizes onboarding operations by combining:
- structured employee onboarding records,
- workflow/task orchestration,
- in-app notifications and event history,
- analytics visibility,
- retrieval-grounded AI assistance for onboarding policy Q&A.

## 2) User Roles
Based on implemented auth and access checks:
- `admin` and `hr_admin`:
  - can create/update employees,
  - can create/update workflows,
  - can add tasks to workflows.
- authenticated users (all roles):
  - can view their profile/session,
  - can view workflows/tasks/progress,
  - can update task status,
  - can use notifications, analytics, and AI assistant endpoints.

## 3) Login Flow
1. User opens `/login`.
2. Frontend submits credentials to `POST /api/v1/auth/login`.
3. Backend validates credentials and user active status.
4. Backend issues JWT and stores it in an `httpOnly` cookie (`access_token`).
5. Frontend stores returned user object in Zustand auth store and redirects to `/dashboard`.
6. On app boot, `AuthBootstrap` calls `GET /api/v1/auth/me` to restore session.

## 4) Dashboard Walkthrough
Dashboard gives a single-pane operational snapshot:
- KPI cards:
  - total workflows,
  - active/completed workflows,
  - total employees,
  - pending/in-progress/completed task counts,
  - average completion.
- Visual analytics:
  - workflow state distribution,
  - task distribution chart,
  - completion trend over recent workflows.
- Operational feed:
  - recent workflows with progress and status,
  - recent notification events.

Data sources:
- `GET /api/v1/analytics/dashboard`
- `GET /api/v1/onboarding/workflows`
- `GET /api/v1/notifications`

## 5) Employee Onboarding Creation Flow
1. Navigate to **New Employee** (`/employees/new`).
2. Fill employee form (name, work email, department, designation, joining date, optional manager).
3. The live preview shows the auto-generated company email (firstname.lastname@company.local).
4. Submit triggers `POST /api/v1/employees`.
5. Backend creates employee record and generates the company email.
6. Backend sends a **welcome email** to employee, manager, and HR containing:
   - Employee Name, Employee ID, Company Email, Department, Designation, Start Date, Workflow Status.
7. Employee service invokes orchestration bootstrap (`OrchestrationService.orchestrate_for_employee`).
8. Company email is stored on the employee record and visible throughout the UI.

## 6) Workflow Orchestration Flow
LangGraph-driven orchestration runs from employee/workflow/task state:
1. Ensure workflow exists (or create initial workflow).
2. Build graph state including employee metadata and existing tasks.
3. Invoke LangGraph nodes:
   - initialize workflow,
   - generate HR tasks,
   - generate provisioning tasks,
   - generate meeting tasks,
   - generate document-sharing tasks,
   - derive state/completion/escalations.
4. Persist generated tasks (deduplicated by stage/title).
5. Persist orchestration events and escalations in audit table.
6. Update workflow state/completion and employee onboarding status.
7. Generate in-app notifications for admins/manager/task assignees.
8. Send **milestone emails** to employee, manager, and HR when workflow reaches:
   - Onboarding Started (initiated)
   - HR Review Completed (provisioning state entered)
   - IT Provisioning Completed (meetings_scheduled state entered)
   - Documents Shared
   - Onboarding Completed

## 7) Task Management Flow
From workflow detail page (`/onboarding/:workflowId`):
1. Load workflow, tasks, and progress.
2. Add task (admin/hr_admin) via `POST /api/v1/onboarding/workflows/{id}/tasks`.
3. Update task status via `PATCH /api/v1/onboarding/tasks/{task_id}`.
4. Backend syncs workflow state after task changes.
5. Completion and event trail update automatically.

## 8) Notification Flow
Notification events are generated by service-layer actions:
- workflow start/transition/completion,
- task assignment/completion,
- AI indexing completed,
- escalations for overdue tasks.

User operations:
- list notifications: `GET /api/v1/notifications`
- unread count: `GET /api/v1/notifications/unread-count`
- mark one read: `PATCH /api/v1/notifications/{id}/read`
- mark all read: `PATCH /api/v1/notifications/read-all`

Frontend behavior:
- periodic polling for notification list and unread count.
- optional WebSocket hook exists client-side but backend WebSocket endpoint is not implemented.

## 9) Analytics Flow
Analytics service computes aggregates directly from workflows/tasks/employees:
- workflow counts by state,
- task counts by status,
- employee counts by onboarding status,
- average completion percentage.

Endpoint:
- `GET /api/v1/analytics/dashboard`

Presented in:
- dashboard summary cards/charts,
- dedicated analytics page.

## 10) AI Assistant Flow
### Document ingestion
1. Upload PDF to `POST /api/v1/rag/documents/upload`.
2. Backend validates file type/size.
3. Text extraction via PDF parser.
4. Chunking via recursive text splitter.
5. Embedding generation via LiteLLM-backed embeddings client.
6. Chunk vectors stored in per-user Chroma collection (`user_{user_id}`).
7. Notification emitted for indexing completion.

### Grounded chat
1. User asks question in assistant UI.
2. Backend semantic-searches relevant chunks.
3. Context is assembled with source references.
4. LCEL chain (`prompt | llm | parser`) generates answer.
5. Response returns answer + cited sources + session id.

## 11) End-to-End Onboarding Demo Scenario
Demo scenario: **Create employee -> orchestrate tasks -> complete selected tasks -> observe status/notifications/analytics -> ask AI policy question**

1. Login as HR/admin user.
2. Open **Create Employee** and submit a new hire.
3. Open **Onboarding Workflows** and locate generated workflow.
4. Open workflow detail and show auto-generated tasks.
5. Mark a few tasks as completed.
6. Show updated completion %, state progression, and orchestration events.
7. Open **Notifications** and show task/workflow event notifications.
8. Open **Analytics** and show changed aggregates.
9. Open **AI Assistant**:
   - upload a policy PDF (if not already indexed),
   - ask onboarding policy question,
   - show citations.

## 13) Verified Gaps / Future Scope
These are intentionally not presented as implemented:
- backend WebSocket notifications endpoint is not implemented,
- email delivery is currently a placeholder method,
- calendar sync integrations are not implemented,
- frontend workflow snapshot API path currently expects `/snapshot` while backend exposes `/orchestration`.
